# SAGE — Detect-then-Veto Student Classroom Behavior Recognition

SAGE uses a multi-label VLM to recognize student classroom behaviors
(15 classes, including co-occurring behaviors such as slumping, reclining,
and phone use), then applies a single **auditable geometric re-check (veto)**
layer to overturn incorrect VLM primary judgments: every re-checked claim
must pass a validation-frozen "authority gate" (quantile gate / raw evidence
floor), and only well-supported vetoes take effect.

Frozen protocol: [`docs/veto-algorithm.md`](docs/veto-algorithm.md)
(veto layer design and frozen constants) and
[`docs/ablation_protocol.md`](docs/ablation_protocol.md) (ablation fairness
protocol). The paper cites both documents as part of the released code.

## Repository Layout

| Tracked (git) | Contents |
|---|---|
| `sage/` | Core library: taxonomy, veto, fusion, eval harness, paths |
| `sage_check/`, `sage_recheck/` | Constants and the re-check layer (detection / geometry / strategies) |
| `servers/` | Small-model re-check services (human detection / pose / depth / face landmarks) |
| `scripts/` | Unified experiment entry points, training / evaluation / statistics / figure scripts, data conversion (`convert_to_swift.py`) |
| `configs/experiments/` | Experiment registry (YAML) |
| `tests/`, `docs/` | Unit tests and frozen-protocol documents |
| `data/sage_eval/annotations.json` | Evaluation benchmark annotations (the only tracked data file) |

## Installation

```bash
pip install -e ".[infer,eval,servers]"   # main environment
```

Running `vlm`-type experiments additionally requires ms-swift (target version
4.4.2, installed into the same environment):

```bash
pip install 'ms-swift[llm]'
```

## Training Reproduction

**1. Data preparation** (needed once per new environment): place images under
`data/sage_eval/images/`, then generate the ms-swift training data
(`train/val/test.jsonl`):

```bash
python scripts/convert_to_swift.py
```

The 80/10/10 multi-label stratified split is frozen in
`data/sage_eval/annotations.json` — do not re-split it.

**2. One-command training**: a single command runs
**training → checkpoint discovery → automatic eval services → evaluation
report** (training and evaluation artifacts are written to the local
`checkpoints/` and `results/` directories and are not committed; frozen
verification artifacts under `results/released/` are the exception and are
tracked):

```bash
python scripts/run_experiment.py --config configs/experiments/d1_bce_nomp_s42.yaml
```

- **Idempotent**: existing evaluation reports are skipped; `--force` re-runs;
  `--dry-run` only prints commands
- **Batch**: `--config configs/experiments` runs the whole registry
  (`--until 24` caps total hours)
- **Multi-GPU**: `--gpus "0,1,2,3" --parallel 2` (one GPU per experiment,
  parallel scheduling)
- **Registry**: `python scripts/run_experiment.py --list` (includes progress
  and notes)

Registry overview (use `--list` for the authoritative list):

| Experiment | Description |
|---|---|
| `d1_bce_mp_s4{2,3,4}` | Main result: CE+BCE+multi-positive hybrid-loss VLM (three seeds, ~11 h each on A10 24 GB) |
| `d1_bce_nomp_*`, `d1_ce_only_*` | Loss-channel ablations |
| `yolo_grid_*`, `resnet_grid_*`, `yolobce_grid_*` | Small-model classification baseline grids (data built by `scripts/prepare_yolo_cls.py`) |
| `d0_zeroshot_s42`, `e2_*` | Zero-shot baseline and primary-judgment decision-rule comparison (eval_only) |

## Evaluation Reproduction

**VLM primary judgment and decision rules** (eval_only type; no manual
service startup needed — the runner manages services automatically):

```bash
python scripts/run_experiment.py --config configs/experiments/d0_zeroshot_s42.yaml
python scripts/run_experiment.py --config configs/experiments/e2_primary_argmax_s42.yaml
```

**Veto pipeline** (requires the small-model re-check services to be online):

```bash
bash servers/start_servers.sh        # 8001 human detection / 8002 pose / 8003 depth / 8005 landmarks
python scripts/run_experiment.py --config configs/experiments/e3_collect_val_s42.yaml
python scripts/run_experiment.py --config configs/experiments/e3_fit_s42.yaml
python scripts/run_experiment.py --config configs/experiments/e3_freeze_s42.yaml
python scripts/run_experiment.py --config configs/experiments/e3_eval_s42.yaml
pkill -f 'servers.*_server'          # stop after use
```

The equivalent manual entry point is
`python scripts/eval_veto.py --stage collect|fit|eval` (see the script header
for usage). Run all three seeds (s42/s43/s44).

**E4 comparison** (none / veto / fusion / removal-only, same evidence input):

```bash
PYTHONPATH=. python scripts/e4_fusion.py --help
```

**Paper statistics**: McNemar, bootstrap, calibration, etc. are computed by
`scripts/stats_tests.py` and the `compute_*` scripts; figures and tables are
regenerated by `gen_paper_figures.py`, `gen_paper_tables.py`, and
`export_curves.py`.
