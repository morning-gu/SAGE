# 02 评测数据集构建方案

> 目标：构建面向"学生学习行为监测"的评测+训练数据集，单帧标注，15 个原子行为多标签
> 更新：从帧对改为单帧（文档 10 决策）；增加 train/val/test 划分（微调需要）
> 日期：2026-08-15

---

## 1. 设计原则

1. **单帧标注**：每帧独立标注 15 个原子行为，不需要帧对配对
2. **多标签**：每帧可有多个原子行为同时为真（如低头+闭眼）
3. **真实性优先**：数据来源于 StudyBuddyAgent 系统实际运行场景
4. **双人标注 + 裁决**：报告 Cohen's kappa
5. **类别均衡**：少数类每类至少 30 个正样本

---

## 2. 标注体系

### 2.1 15 个原子行为标签

| ID | 中文 | 英文 label | 说明 |
|---|---|---|---|
| 0 | 正常 | normal | 坐姿端正，视线在学习材料上，手部有学习动作 |
| 1 | 离座 | away | 画面中无人或人不在座位 |
| 2 | 遮挡 | blocked | 画面被遮挡超过50%，无法判断 |
| 3 | 玩玩具 | toy | 手持非学习物品玩耍 |
| 4 | 玩电子设备 | phone | 手持手机/平板，视线在屏幕 |
| 5 | 吃零食 | snack | 手持食物，靠近嘴部 |
| 6 | 闭眼 | sleepy | 眼睛闭合（单帧，眨眼也算） |
| 7 | 趴桌 | prone | 上身前倾超45度，头部贴近桌面 |
| 8 | 低头 | bowed | 头部明显前倾，鼻尖低于肩部连线 |
| 9 | 斜肩 | slope | 肩部左右明显不水平 |
| 10 | 仰躺 | recline | 身体后仰靠在椅背上 |
| 11 | 仰头 | lookup | 头部明显后仰 |
| 12 | 歪头 | tilt | 头部明显向左或右侧偏 |
| 13 | 转头 | turn | 头部转向侧面（单帧可判） |
| 14 | 托腮 | chinrest | 双手支撑下巴或面颊（单手不算） |

### 2.2 主导类别选择规则

当多个行为同时为真时，标注一个"主导类别"。标注者根据视觉理解判断哪个行为最能代表学生的当前状态（不设固定优先级排序）。

> **架构说明**：模型同样基于视觉理解自行判断主导类别。最终主导类别由业务逻辑层结合各类别概率与模型判断结果通过算法确定。当前框架仅输出数据（15 类 sigmoid 概率 + 模型判断的主导类别），业务逻辑层暂未实现。

### 2.3 标注细则

- **闭眼**：单帧标注。正常眨眼也算"闭眼=1"，本研究不涉及时序区分
- **转头**：单帧标注。头部转向侧面即为"转头=1"，东张西望不在本研究范围内
- **遮挡 vs 离座**：画面完全无人 -> away；画面有人但被遮挡 -> blocked
- **低头 vs 趴桌**：鼻尖低于肩部但上身未贴桌面 -> bowed；上身前倾超45度头部贴桌面 -> prone
- **托腮**：单手撑下巴不算托腮；双手支撑下巴或面颊才算 chinrest

## 3. 数据采集

### 方案 A：从生产日志采样（推荐）

从 AnomalyDetectorNode 处理过的日志中提取已处理的单帧图像：
- 按 user_id 分组，每用户随机采样 10-15 帧
- 按系统检测结果分层采样，确保类别覆盖
- 目标总量：800 单帧

### 方案 B：定向采集（补充少数类）

对样本不足的少数类（托腮/玩玩具/吃零食），组织定向采集：
- 招募 10-15 名志愿者
- 每个行为采集 10-15 帧
- 记录场景元数据（书桌/光照/摄像头角度）

---

## 4. 标注流程

1. 编写标注指南（含图例和边界 case）
2. CVAT 或 Label Studio 标注工具
3. 标注员 A、B 独立标注全部样本
4. 计算 Cohen's kappa（目标 >= 0.70）
5. 分歧样本由裁决员判定
6. 随机抽 10% 第三人验证

---

## 5. 数据集统计与划分

### 目标统计

| 类别 | 目标正样本数 |
|---|---|
| normal | 200 |
| away | 50 |
| blocked | 50 |
| prone/bowed | 各50 |
| tilt/slope/lookup/recline/chinrest | 各30 |
| toy/phone/snack | 各30 |
| sleepy/turn | 各30 |
| **总帧数** | **800** |

### 划分策略

| 集合 | 来源 | 样本量 | 用途 |
|---|---|---|---|
| Train | 人工70% + LLM生成 | ~2500-3000 | LoRA 微调 |
| Val | 人工15% | ~100 | 温度缩放+早停+每类别阈值 |
| Test | 仅人工15% | ~100-150 | 最终评估（高质量） |

**关键原则**：Test 集只用人工标注样本。按 user_id 分组划分，防止泄漏。

### LLM 生成扩充

用 Qwen3-VL-32B 对未标注图像生成标签（详见文档 03 第 4 节 LLM 生成管线）：
- Stage 1: 32B few-shot 生成标签+解释
- Stage 2: 32B 独立验证
- Stage 3: 一致性过滤
- Stage 4: 人工抽检 10%
- 最终 2000-3000 样本，loss 权重 0.5-0.8

---

## 6. 数据格式

### 目录结构

studybuddy_eval/
  images/
    frame_0001.jpg
    frame_0002.jpg
    ...
  annotations.json
  metadata.json

### annotations.json

每条记录：
- sample_id, image, source(manual/llm_generated/verified_llm), source_weight(1.0/0.5/0.8)
- labels: {normal:0, away:0, ..., prone:1, bowed:1, ...}（15个二值）
- primary_label: "bowed"（主导类别）
- messages: [system, user(image+text), assistant(classify-then-explain输出)]
- metadata: user_id, scene_type, lighting, camera_angle

---

## 7. 伦理与隐私

- 知情同意书（含监护人签署）
- user_id 脱敏
- 未成年人 IRB 审批
- 评测数据不公开原始图像

## 8. 时间线

| 阶段 | 内容 | 时间 |
|---|---|---|
| 1. 数据采样 | 从日志提取单帧 | 1.5 天 |
| 2. 标注指南 | 编写规则+图例 | 2 天 |
| 3. 试标注 | 20样本校准 | 1 天 |
| 4. 正式标注 | 800帧双人标注 | 4-5 天 |
| 5. 裁决+质检 | kappa计算+抽检 | 2 天 |
| 6. LLM生成 | 管线执行 | 2 天 |
| 7. 合并划分 | 格式转换+划分 | 1 天 |
| **合计** | | **约 2.5 周** |
